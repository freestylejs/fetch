## Overview

The `create-freestyle-fetch` creates [**Zod schemas**](https://zod.dev/) for all data types in your API specification.

 These schemas provide runtime validation for requests and responses, ensuring type safety at both compile-time and runtime.

## Automatic Validation

### A. Response Validation

All responses are automatically validated before being returned:

```typescript
const user = await client.users.$userId.GET.query({
  path: { userId: '123' }
})

// If the response doesn't match the User schema, Zod throws an error
// Otherwise, user is guaranteed to match UserModel
```

The validation happens in the `.def_response()` method:

```typescript
.def_response(async ({ json }) => Schemas.parseUser(await json()))
```

### B. Request Body Validation

Request bodies are validated using the `.def_body()` method:

```typescript
POST: f.builder()
  .def_json()
  .def_body(Schemas.parseCreateUser)
```

When you make a request, the body is validated:

```typescript
await client.users.POST.query({
  body: {
    username: 'john',
    email: 'invalid-email' // ❌ Zod error: Invalid email
  }
})
```

### C. Query Parameter Validation

Query parameters are validated with `.def_searchparams()`:

```typescript
GET: f.builder()
  .def_json()
  .def_searchparams(z.object({
    page: z.number().optional(),
    limit: z.number().max(100).optional()
  }).parse)
```

Invalid query parameters throw errors:

```typescript
await client.users.GET.query({
  search: {
    page: 1,
    limit: 200 // ❌ Zod error: Number must be less than or equal to 100
  }
})
```

## Handling Validation Errors

### A. Zod Error Structure

When validation fails, Zod throws a `ZodError`:

```typescript
import { ZodError } from 'zod'

try {
  const user = await client.users.$userId.GET.query({
    path: { userId: '123' }
  })
} catch (error) {
  if (error instanceof ZodError) {
    console.error('Validation failed:', error.errors)
    // [{ path: ['email'], message: 'Invalid email' }]
  }
}
```

### B. Custom Error Handling

Use the fetch builder's error handlers for more control. Define them on the generated
client by extending a builder before `.build()`, or handle errors at the call site with
`try/catch`:

```typescript
import { f } from '@freestylejs/fetch'
import { ZodError } from 'zod'

try {
  const user = await client.users.$userId.GET.query({
    path: { userId: '123' }
  })
} catch (error) {
  if (error instanceof ZodError) {
    // Handle validation errors
    console.error('Data validation failed:', error.flatten())
  } else {
    // Handle other errors
    console.error('Request failed:', error)
  }
}
```

For reusable handling, compose your own unit from the library's builder primitives:

```typescript
const safeGetUser = f.builder()
  .def_url('https://api.example.com/users/$userId')
  .def_json()
  .def_response(async ({ json }) => Schemas.parseUser(await json()))
  .def_unknown_err_handler(({ error }) => {
    console.error('Network failure:', error)
  })
  .build()

await safeGetUser.query({ path: { userId: '123' } })
```

## Schema Constraints

The generator translates OpenAPI constraints to Zod:

### A. String Constraints

```typescript
// OpenAPI
{
  "type": "string",
  "minLength": 3,
  "maxLength": 50,
  "pattern": "^[a-zA-Z]+$"
}

// Generated Zod
z.string().min(3).max(50).regex(/^[a-zA-Z]+$/)
```

### B. Number Constraints

```typescript
// OpenAPI
{
  "type": "number",
  "minimum": 0,
  "maximum": 100
}

// Generated Zod
z.number().min(0).max(100)
```

### C. Array Constraints

```typescript
// OpenAPI
{
  "type": "array",
  "items": { "type": "string" },
  "minItems": 1,
  "maxItems": 10
}

// Generated Zod
z.array(z.string()).min(1).max(10)
```

### D. Object Constraints

```typescript
// OpenAPI
{
  "type": "object",
  "required": ["name", "email"],
  "properties": {
    "name": { "type": "string" },
    "email": { "type": "string", "format": "email" },
    "age": { "type": "integer" }
  }
}

// Generated Zod
z.object({
  name: z.string(),
  email: z.email(),
  age: z.number().int().optional()
})
```

## Advanced Validation

### A. Nullable Types (OAS 3.1)

The generator supports OpenAPI 3.1 nullable types:

```typescript
// OpenAPI
{
  "type": ["string", "null"]
}

// Generated Zod
z.string().nullable()
```

### B. Enums

Enums are converted to Zod enums:

```typescript
// OpenAPI
{
  "type": "string",
  "enum": ["active", "inactive", "pending"]
}

// Generated Zod
z.enum(['active', 'inactive', 'pending'])
```

### C. Discriminated Unions

The generator creates discriminated unions for `oneOf` with discriminators:

```typescript
// OpenAPI
{
  "oneOf": [
    { "$ref": "#/components/schemas/Cat" },
    { "$ref": "#/components/schemas/Dog" }
  ],
  "discriminator": {
    "propertyName": "type"
  }
}

// Generated Zod
z.discriminatedUnion('type', [Cat, Dog])
```

### D. Intersection Types

`allOf` creates intersection types:

```typescript
// OpenAPI
{
  "allOf": [
    { "$ref": "#/components/schemas/BaseEntity" },
    { "$ref": "#/components/schemas/Timestamped" }
  ]
}

// Generated Zod
BaseEntity.and(Timestamped)
```

## Performance Considerations

### A. Schema Caching

Validators are generated once and reused for all requests. Each `parse<Name>` function
closes over a single schema instance:

```typescript
// Generated once in schemas.js
const User = z.object({
  id: z.string(),
  name: z.string()
})

export const parseUser = (value) => User.parse(value)
// parseUser reuses the same schema on every call — no recreation
```

### B. Non-throwing Validation

Generated parsers throw on invalid data. If you need non-throwing checks, run your own
schema with `.safeParse()`:

```typescript
import { z } from 'zod'

const result = z.object({
  id: z.string(),
  name: z.string()
}).safeParse(data)

if (result.success) {
  const user = result.data
} else {
  console.warn('Invalid user data:', result.error)
}
```
